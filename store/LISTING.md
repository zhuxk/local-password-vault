### 1.2 隐私权规范（Privacy tab）

#### 单一用途（Single purpose）

> 在浏览器本地加密保存网站账号密码，并在登录页自动或手动填充。

#### 权限理由（逐条填写，评审会对照代码核查）

| 权限 | 理由 |
| --- | --- |
| `storage` | 保存本地加密的密码库条目与用户设置（填充方式、默认账号、生成器规则）。数据仅存于浏览器，不上传。 |
| `alarms` | 实现闲置自动锁定（可选 5/15/30/60 分钟）。仅使用本地闹钟触发锁定，不发起网络请求。 |
| `clipboardWrite` | 用户点击"复制账号""复制密码"时，将所选内容写入剪贴板。 |
| `activeTab` | 在扩展弹窗中读取当前标签页地址，以确定当前站点并只显示该站点的账号。 |
| 主机权限 `http://*/*`、`https://*/*` | 密码管理器需要在任意网站的登录表单中识别用户名与密码输入框并完成填充，因此内容脚本必须注入所有 http/https 页面。扩展只读取登录框内容用于填充，不会读取其他页面内容，也不会把任何数据传出设备。 |

#### 远程代码

> 否。扩展包内含全部可执行代码，不加载任何远程脚本。用于识别根域名的 Public Suffix List 已随扩展打包在本地。

#### 数据使用（Data usage）

> **勾选：**
> - ✅ Authentication information（认证信息）— 扩展读取登录表单中的用户名与密码并加密保存在本地密码库中
> - ✅ Website content（网站内容）— 内容脚本读取页面中的登录表单输入框以完成填充
>
> **不勾选：** Personally identifiable information、Personal communications、Financial information、Location、Web history、User activity、Health information
>
> **Limited Use 认证三项全部勾选：**
> - ✅ 数据未被出售给第三方
> - ✅ 数据未被用于与扩展核心功能无关的目的
> - ✅ 数据未被用于信用评估或贷款用途
>
> 上述数据全部只保存在用户浏览器本地，**不会传输到任何服务器**。

#### 隐私政策 URL

> ✅ `https://zhuxk.github.io/local-password-vault/`

（已通过 GitHub Pages 上线，仓库 `zhuxk/local-password-vault` 的 `docs/` 目录即站点根。未登录可直接访问并返回 200。）

> 备选：`https://zhuxk.github.io/local-password-vault/` 与 `https://zhuxk.github.io/local-password-vault/index.html` 等价。

### 1.4 详细说明

```
本地密码匣是一个完全离线的密码管理器：所有账号密码都用主密码派生的密钥加密后保存在你自己的浏览器里，不经过任何服务器，也没有账号系统。

■ 完全本地存储
密码库使用 AES-256-GCM 加密，密钥由你的主密码通过 PBKDF2-SHA256（310,000 次迭代）派生。主密码从不被保存，也无法找回。扩展不包含任何统计、埋点或广告代码，不会发起任何网络请求。

■ 自动填充
登录页识别出唯一的用户名与密码框后自动填入，但绝不替你点击登录按钮——提交动作永远由你自己决定。同一个网站有多个账号时，密码框旁会出现一个"钥"按钮，点开就能选择要填入的账号。

■ 每个站点都能单独控制
网站可以选择"自动填充""仅点击填充"或"禁用"三种模式，敏感的后台系统可以完全关掉自动识别。

■ 密码历史
修改密码后自动保留最近 3 次旧密码，随时可以查看、复制或一键回退。

■ 备份与恢复
导出的备份文件仍然是密文，可以放心存放或转移；在另一台设备上用同一个主密码即可完整恢复。

■ 域名规则清晰
example.com 与 www.example.com 视为同一站点，admin.example.com 等其他子域名各自独立；内网 IP 按端口分别管理，避免内网账号互相混淆。

■ 闲置自动锁定
5 / 15 / 30 / 60 分钟无操作自动锁定，可在管理页随时调整。

■ 导入浏览器已有密码
支持导入 Chrome / Edge 导出的密码 CSV，一次性完成迁移。

■ 密码生成器
可设置长度并自由组合大小写字母、数字与符号，自动排除容易混淆的字符。

适合想摆脱云端密码库、只想把密码留在本机的人。
```

## 三、审核备注（Notes for certification）

这段话能显著减少来回补材料，Chrome 与 Edge 都填。

```
这是一个纯本地的密码管理器扩展，没有服务器、没有账号系统，也不需要联网。

测试步骤：
1. 点击工具栏的"本地密码匣"图标，弹窗会提示"创建密码库"。
2. 输入任意不少于 8 个字符的主密码两次（例如 test1234 / test1234），点击"创建并解锁"。
   注意：主密码无法找回，请勿使用您真实的密码。
3. 弹窗中点击"添加当前站点账号"，填写用户名和密码后保存。
4. 点击底部"管理全部密码与导入"打开管理页，可以看到刚才保存的账号，
   页面按根域名分组，并提供搜索、排序、密码历史、回收站与备份导出。
5. 若要体验网页填充，请访问任意一个登录页（例如 https://example.com/login）。
   扩展会自动识别登录框并填入账号密码；密码框旁会出现一个"钥"按钮，
   当同一站点有多个账号时，点开它可以切换要填入的账号。
   扩展只填充、不会自动提交登录表单。

可选测试数据（可在管理页"导入浏览器 CSV"中导入）：
url,username,password
https://example.com/,test@example.com,Test1234!
https://admin.example.com/login,admin,Admin1234!

需要说明的实现细节：
- 密码库整体使用 AES-256-GCM 加密，密钥由主密码通过 PBKDF2-SHA256（310000 次迭代）派生。
- 主密码仅存在于内存中，从不写入存储。
- 请求 http://*/* 与 https://*/* 主机权限，是因为密码管理器必须在任意站点的登录表单中
  识别输入框并完成填充。内容脚本仅读取登录表单相关的内容，不会采集页面其他信息。
- 扩展不发起任何网络请求；用于识别根域名的 Public Suffix List 已随扩展打包在本地。
- 闲置自动锁定默认 15 分钟，可在管理页"安全设置"中调整为 5 / 15 / 30 / 60 分钟。
```

## 四、常见驳回原因自查

| 症状 | 原因 | 处理 |
| --- | --- | --- |
| 上传报 "description field in manifest is too long" | manifest description 超过 132 字符 | 精简 manifest 里的 description，详细说明放到商店表单里 |
| 报 "could not find manifest.json" | 把整个文件夹压进去了 | manifest.json 必须在 zip 根目录，用 `tools/package.sh` |
| 截图被驳回 | 截图与描述不符，或是纯文字图 | 用 `store/screenshots/` 里的真实界面截图 |
| 隐私政策 URL 打不开 | 返回 404 或需要登录 | 部署到 GitHub Pages 后确认公开可访问 |
| 权限理由被质疑 | 理由太笼统 | 用 1.2 节里逐条的具体理由 |
| 数据使用被质疑 | 少勾了数据类型 | 本扩展必须勾 Authentication information 与 Website content |
| 更新提交被拒 | 版本号没有提高 | 每次上传前提高 manifest 里的 version |

## 五、发布后的维护

- 每次改代码后：提高 `manifest.json` 的 `version`，运行 `bash tools/package.sh --edge`，重新上传。
- Chrome 用户会在审核通过后数小时内自动收到更新。
- 如果扩展新增了权限或改变了数据处理方式，**必须先更新隐私政策页面**，再提交审核。
- 两个商店的文案应保持一致，只有商店特有的字段（Edge 的年龄分级、搜索词）不同。
